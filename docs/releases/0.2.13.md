> Sound recovers when the output shows up late, the Inpulse 500 master meter lights up, and releases build in a fraction of the time.

## Fixes

- **No sound at start ([#57](https://github.com/OpenRsG/OpenFadeR/issues/57)).** If the sound output was missing or busy when the app started, the decks stayed disabled for good and tracks would not play. The app now retries the chosen output every second and plays as soon as it appears. The deck status and the diagnostics report say why there is no sound; AUTOMIX, preview and REC no longer pretend to work without an output.
- **Hercules DJControl Inpulse 500 ([#49](https://github.com/OpenRsG/OpenFadeR/issues/49)).** The master VU meter and the master peak and clip lights are driven (mapping `openfader-v0.2.13`).
- **Restore.** A backup that holds a relative path can no longer restore a file outside its own folder.

## Docs

- New guide: [Backup, export and sync, also between two computers](https://github.com/OpenRsG/OpenFadeR/blob/v0.2.13/docs/backup-export-sync.md) ([#56](https://github.com/OpenRsG/OpenFadeR/issues/56)).

## Build

- Releases build in about 27 minutes instead of 3 hours: the compiler uses every core, the UI crate is compiled once, and macOS builds in two parallel jobs.

## Please test

- [#57](https://github.com/OpenRsG/OpenFadeR/issues/57) on a real Raspberry Pi and [#49](https://github.com/OpenRsG/OpenFadeR/issues/49) on a real Inpulse 500: both were checked on x86 with a software setup only.
